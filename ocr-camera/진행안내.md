# 세션 진행 안내 — 카메라 OCR

2026. 9. 15. (화) · 2시간 · 3명

오늘은 **각자 자기 손으로 쳐서** 폰 카메라 → 노트북 서버 → OCR 을 굴립니다.
붙여넣기 없습니다. 그게 오늘의 요점입니다.

끝나면 각자 자기 폰에서 자기가 친 앱이 돌아가 있어야 합니다.

## 왜 따라치게 하는가

지난 학기 결과물이 전부 돌아갔지만, 아무도 자기 코드를 설명하지 못했습니다.
붙여넣으면 안 될 때 어디를 볼지 모릅니다.

오늘 칠 양은 서버 70줄, 앱 75줄입니다. 30분이면 칩니다.
**대신 안 될 때 스스로 고칠 수 있게 됩니다.** 오늘 절반은 안 될 겁니다. 그게 정상이고, 그게 수업입니다.

**사전준비를 안 해온 사람이 있으면 그 사람은 오늘 못 합니다.** 전날 확인하세요.

[사전준비.md](사전준비.md) 를 단톡에 던지고, 전날 밤에 다섯 줄 체크리스트를 받으세요.

- Node 설치됐나 (`node --version`)

```powershell
(Find-NetRoute -RemoteIPAddress 8.8.8.8)[0].IPAddress
```

`169.254`로 시작하면 와이파이에 제대로 못 붙은 겁니다. 폰에서 접속 안 됩니다.

## 1부 — 왜 서버로 빼는가 (15분)

먼저 물어보세요.

> "OCR을 폰 안에서 바로 하면 안 되나요?"

| 폰에서 직접 | 서버에서 |
|---|---|
| 네트워크 없어도 됨 | 인터넷 필요 |
| 모델을 앱에 넣어야 함 (수십 MB) | 앱은 가벼움 |
| 모델 바꾸려면 앱 업데이트 | 서버만 바꾸면 끝 |
| 기기 성능에 좌우 | 서버 성능으로 일정 |

**"모델을 바꾸려면 앱을 다시 배포해야 한다"가 핵심입니다.**
5부에서 서버 설정만 바꿔서 동작을 바꿔볼 텐데, 그때 앱은 한 줄도 안 건드립니다.

```
폰 (Expo)  --사진-->  노트북 (FastAPI)  -->  OCR 엔진
           <--결과--
```

## 2부 — 서버 따라치기 (30분)

칠 파일: [server/typing/main.py](server/typing/main.py) · 70줄

각자 자기 노트북에 `main.py`를 새로 만들어서 칩니다.
**화면에 띄워놓고 부르지 말고, 각자 보면서 치게 하세요.** 속도가 달라도 됩니다.

### 치면서 짚을 것

세 군데만 짚으면 됩니다. 나머지는 그냥 치면 됩니다.

**1. 기본값이 중국어입니다**

```python
engine = RapidOCR(params={
    "Rec.lang_type": LangRec.KOREAN,
    ...
})
```

이 세 줄을 안 넣으면 한글을 못 읽습니다. 에러가 나는 게 아니라 **이상한 한자가 나옵니다.**
"돌아가는데 결과가 틀린" 경우라 알아채기 어렵습니다.

**2. EXIF 회전**

```python
img = ImageOps.exif_transpose(img).convert("RGB")
```

폰으로 세로로 찍으면 사진 자체는 가로로 저장되고, "돌려서 보라"는 표시만 EXIF에 붙습니다.
이걸 안 풀면 글자가 누워서 들어가고 인식이 무너집니다.

**3. 크기 줄이기**

```python
MAX_SIDE = 1600
```

폰 사진은 4000px가 넘습니다. 안 줄이면 느립니다. 여기가 5부에서 돌릴 손잡이입니다.

### 다 쳤으면 띄웁니다

```bash
python main.py
```

```
  폰에서 접속할 주소:  http://172.25.0.119:8000
```

**이 주소를 각자 적어두게 하세요.** 사람마다 다릅니다.

### 앱 붙이기 전에 서버만 확인합니다

이 순서가 중요합니다. 나중에 안 될 때 서버 문제인지 앱 문제인지 바로 갈립니다.

```bash
curl http://localhost:8000/health
curl -F "file=@../../../ocr-intro/samples/01_clean.png" http://localhost:8000/ocr
```

`영수증 합계 12500원` 이 나오면 서버는 끝난 겁니다.

### 그다음 폰 브라우저로

```
http://내주소:8000/health
```

`{"ok": true}` 가 폰에서 보이면 **오늘 세션은 무조건 굴러갑니다.**
여기서 막히는 사람은 방화벽 → 와이파이 순으로 봅니다.

## 3부 — 앱 따라치기 (35분)

칠 파일: [app/typing/App.js](app/typing/App.js) · 75줄

사전준비에서 만들어둔 `ocr-app` 폴더의 `App.js`를 지우고 새로 칩니다.

**맨 위 한 줄을 자기 주소로 바꾸는 걸 빼먹는 사람이 반드시 나옵니다.**

```js
const SERVER = 'http://192.168.0.10:8000';
```

### 치면서 짚을 것 — 여기가 오늘의 함정입니다

```js
const form = new FormData();
form.append('file', { uri: shot.uri, name: 'photo.jpg', type: 'image/jpeg' });
const res = await fetch(SERVER + '/ocr', { method: 'POST', body: form });
```

**두 가지가 낯섭니다.**

첫째, React Native에서는 파일을 `{ uri, name, type }` 객체로 넣습니다. 웹이랑 다릅니다.

둘째, `headers`에 `Content-Type`을 직접 쓰면 안 됩니다.
직접 쓰면 boundary가 빠져서 서버가 파일을 못 읽습니다.
**에러 메시지가 안 친절해서 이걸로 한 시간 날리는 경우가 흔합니다.**

일부러 한번 넣어보게 하고 서버 로그를 보여주는 것도 방법입니다.

### 실행

```bash
npx expo start
```

폰의 Expo Go로 QR을 찍습니다. 카메라 권한을 물으면 허용합니다.

## 4부 — 각자 폰으로 찍어보기 (20분)

**서버 띄운 터미널을 각자 보이게 두고 하세요.** 요청이 찍히는지 아닌지가 문제를 반으로 가릅니다.

```
photo.jpg  (4032, 3024) -> (1600, 1200)  221KB  942.2ms  덩어리 1
```

### 안 될 때 순서

| 증상 | 볼 것 |
|---|---|
| **서버 로그에 아무것도 안 찍힘** | 요청이 도달을 못 한 것. 앱이 아니라 네트워크. 주소 → 방화벽 → 와이파이 |
| Network request failed | `SERVER` 주소 오타. `http://` 빠졌는지, 포트 빠졌는지 |
| 로그는 찍히는데 결과가 빈 문자열 | 글자가 너무 작음. 화면을 꽉 채워서 다시 |
| 한자가 나옴 | `Rec.lang_type` 안 넣은 것 |
| 글자가 누워서 인식 | `exif_transpose` 빠뜨린 것 |
| 첫 요청만 수십 초 | 모델을 그때 받는 중. 사전준비를 안 한 것 |

### 다 되면 한번 해볼 것

**세 명이 전부 트랙장 서버 주소로 바꿔서 동시에 찍어보세요.**

한 대에 세 명이 붙으면 응답이 느려집니다. 서버 로그에 세 사람 요청이 섞여 들어옵니다.
"서버는 공유 자원"이라는 게 말이 아니라 숫자로 보입니다.

## 5부 — 손잡이 돌리기 (15분)

**바꾸기 전에 예측을 먼저 적게 하세요.** 적고 나서 돌립니다.

| 바꿀 것 | 어디 | 예상은? |
|---|---|---|
| `quality: 0.7` → `1.0` | `App.js` | 업로드가 커진다. OCR 시간도 늘어날까? |
| `MAX_SIDE = 1600` → `800` | 서버 | 빨라진다. 정확도는? |
| `MAX_SIDE = 1600` → `3200` | 서버 | 정확해질까? 느려지는 만큼 값어치를 할까? |

### 실측 참고값 (트랙장 노트북)

폰 사진 크기 4032×3024 JPEG 221KB 기준

| | OCR 시간 |
|---|---:|
| 1600px로 줄여서 | **780~940ms** |

깨끗한 샘플 인식 결과

```
영수증 합계 12500원      신뢰도 1.00
주문번호 A-2026-0908     신뢰도 0.98
```

**여기서 오늘의 요점입니다.** `MAX_SIDE`는 서버에만 있습니다.
바꿔도 앱은 한 줄도 안 건드리고, 폰에서 다시 깔 것도 없습니다.
1부에서 얘기한 "서버만 바꾸면 끝"이 여기서 눈으로 확인됩니다.

### 신뢰도 얘기

깨끗한 이미지인데도 가끔 이런 게 섞여 나옵니다.

```
1.00  영수증 합계 12500원
0.31  |
```

마지막 `|`는 이미지 테두리를 글자로 잡은 겁니다.
**결과만 보면 "잘 됐다"고 넘어갑니다. 신뢰도를 봐야 보입니다.**

앱에서 0.5 미만은 빨간색으로 찍게 해놨습니다. 빨간 게 왜 나왔는지 물어보세요.

## 다 친 다음에

완성본과 비교하게 하세요.

| 친 것 | 완성본 | 뭐가 더 있나 |
|---|---|---|
| `server/typing/main.py` | `server/main.py` + `server/engines.py` | 엔진 교체, `/stats`, 환경변수 |
| `app/typing/App.js` | `app/App.js` | 측정값 표시, 에러 안내, 스타일 |

**`engines.py`를 같이 여세요.** `main.py`는 어떤 OCR 엔진을 쓰는지 **모릅니다.**
그래서 엔진만 갈아끼우면 OCR 자리에 이미지 분류든 객체 탐지든 들어갈 수 있습니다.

그게 이번 학기 프로젝트의 뼈대입니다.

## 알아둘 것 — 이 노트북에서 EasyOCR은 못 씁니다

```
Smart App Control: 켜짐
import torch -> OSError [WinError 4551] 애플리케이션 제어 정책에서 이 파일을 차단
```

Windows 11의 Smart App Control이 torch의 서명 없는 DLL을 막습니다.
그래서 torch를 안 쓰는 onnxruntime 기반 RapidOCR을 씁니다. 한국어 모델이 정식 지원됩니다.

**질문이 나오면 좋은 얘깃거리입니다.** "내 노트북에선 되는데 저긴 안 된다"가
왜 생기는지, 그래서 왜 의존성을 줄이는 쪽으로 설계하는지로 이어집니다.
